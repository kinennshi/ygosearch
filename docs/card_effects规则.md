# card_effects 效果精修规则（实现规格书）

> 版本：v1.0（2026-09-29）
> 地位：自然语言卡片检索系统的**离线语义索引层**的构建规则
> 读者：负责实现该模块的工程师或 LLM。按本文档可直接编码，不需要额外询问。

---

## 0. 这是什么

把 `cards.cdb` 里每张卡的效果文本（`texts.desc`）**离线**拆解成"效果段"，给每个效果段打上结构化标签，落成一张 SQLite 派生表 `card_effects`。查询期不再解析原文，只做 SQL。

它在系统中的位置：

```
用户自然语言
  → LLM 理解层（输出筛选 DSL，带 Schema 约束）
  → 校验层（枚举白名单对齐）
  → 执行层：一条 SQL，三个条件 AND：
      ① 卡片标量条件（type/attribute/level/race/setname/atk/def）
      ② category 位粗筛（官方 32 位动作类型，见 §6）
      ③ card_effects EXISTS 精修（本模块的产物，五维 + 段级绑定）
  → 结果 + 命中理由回显 → 多轮增量修改
```

**核心原则：理解归 LLM，检索全走确定性路径。本模块只负责把文本变成可检索的结构，不做任何在线推理。**

## 1. 输入数据

| 资产 | 路径 | 说明 |
|---|---|---|
| 卡池（简中） | `cdb/zh-CN/cards.cdb` | SQLite，15,019 张 |
| 卡池（日文） | `cdb/ja-JP/cards.cdb` | **分类权威来源** |
| 卡池（英文） | `cdb/en-US/cards.cdb` | 备用对照 |
| 字符串表 | `cdb/<lang>/strings.conf` | 含 `!system 1100`~`1131`（category 位名） |
| 已导出 JSON | `export/cards_<lang>.json` | 字段已解码，可直接用（与 cdb 等价） |

表结构（三张 cdb 相同）：

- `datas(id, ot, alias, setcode, type, atk, def, level, race, attribute, category)`
- `texts(id, name, desc, str1..str16)`

**三语言 id 一一对应（已全量验证，差集为 0）。**

### 1.1 用哪种语言分类

**分类用 ja-JP，展示用 zh-CN。**

原因（已实测）：中文社区翻译丢失部分模板标记——「为对象」在中文文本出现 4,336 张，日文「対象」5,947 张；时点标记「時」日文 5,130 张，中文「时，」仅 2,358 张。日文是 KONAMI 官方措辞，模板最严格。分类在日文效果段上做，标签通过共享 id 投影，中文仅用于 `text` 字段展示和回显。

### 1.2 datas 关键字段解码（实现时要用）

- `id`：卡片唯一 ID，8 位数字，三语言通用，跨表/跨语言关联的主键
- `type`：位掩码。大类 `&0x1`怪兽 `&0x2`魔法 `&0x4`陷阱；`&0x80`仪式 `&0x2000`同调 `&0x800000`超量 `&0x1000000`灵摆 `&0x4000000`连接 `&0x20`效果 `&0x10`通常 `&0x4000`衍生物
- `attribute`：**属性位掩码**（仅怪兽有意义，魔陷为 0）。`0x01`地 `0x02`水 `0x04`炎 `0x08`风 `0x10`光 `0x20`暗 `0x40`神。通常单选，按位与判断
- `race`：**种族位掩码，64 位整数**（仅怪兽有意义）。`0x1`战士 `0x2`魔法师 `0x4`天使 `0x8`恶魔 `0x10`不死 `0x20`机械 `0x40`水族 `0x80`炎族 `0x100`岩石 `0x200`鸟兽 `0x400`植物 `0x800`昆虫 `0x1000`雷 `0x2000`龙 `0x4000`兽 `0x8000`兽战士 `0x10000`恐龙 `0x20000`鱼 `0x40000`海龙 `0x80000`爬虫类 `0x100000`念动力 `0x200000`幻神兽 `0x400000`创造神 `0x800000`幻龙 `0x1000000`电子界 `0x2000000`幻想魔族，高位还有 `0x4000000000000000`妖怪等。可多选，按位与判断
- `level`：**打包字段**。`&0xff`=等级/阶级/LINK；`>>24`=灵摆左刻度；`>>16 &0xff`=右刻度
- `def`：连接怪兽此列是链接箭头位图（无守备力）
- `atk`/`def`：`-2` 表示 `?`
- `category`：官方 32 位动作类型位掩码（见 §6）
- `alias`：非 0 时指向另一张卡的 id（同名再版/规则当作）
- `setcode`：系列码，每 16 位打包一个系列，低 12 位（`&0xFFF`）是主系列号；系列名对照在 `strings.conf` 的 `!setname` 段（如 `!setname 0x1 正义盟军`）
- `ot`：卡池归属。`1`OCG `2`TCG `3`OCG/TCG `8`简中独有 `9`简中/OCG `11`简中/OCG/TCG

## 2. 输出表结构

```sql
CREATE TABLE card_effects (
    card_id      INTEGER NOT NULL,   -- 对应 datas.id
    effect_no    INTEGER NOT NULL,   -- 1-based；P效果=-1；规则文本段=0
    seg_type     TEXT NOT NULL,      -- 'monster'|'pendulum'|'spell_trap'|'rule'|'flavor'
    text         TEXT NOT NULL,      -- 该段原文（zh-CN，用于回显）
    text_ja      TEXT NOT NULL,      -- 该段原文（ja-JP，分类依据，留档复核）
    targets      INTEGER,            -- 取对象：1 是 / 0 否 / NULL 不适用
    activation   TEXT,               -- 'ignition'起动|'trigger'诱发|'quick'诱发即时|'continuous'永续|'none'无需发动
    location     TEXT,               -- 'hand'|'field'|'grave'|'banished'|'deck'|NULL
    timing       TEXT,               -- 'when_optional'时系选发|'if_optional'场合选发|'if_mandatory'场合必发|NULL
    negate_type  TEXT,               -- 'activation'发动无效|'effect'效果无效|NULL
    seg_category INTEGER NOT NULL DEFAULT 0,  -- 段级 category 位（官方同一套 32 位）
    confidence   TEXT NOT NULL DEFAULT 'rule',-- 'rule'规则判定|'llm'LLM补标|'manual'人工
    PRIMARY KEY (card_id, effect_no, seg_type)
);
CREATE INDEX idx_effects_targets  ON card_effects(targets);
CREATE INDEX idx_effects_category ON card_effects(seg_category);
CREATE INDEX idx_effects_location ON card_effects(location);
```

规模预估：全库约 **24,309 个编号效果段**（已实测）+ 灵摆效果 + 无编号段，总量约 3 万行。

## 3. 效果切分规则

按以下优先级处理每张卡的 `desc`。切分用 **zh 和 ja 各切一次**（结构一致，段数应相同；不一致的记录到异常清单）。

### 3.1 灵摆怪兽（type & 0x1000000）

文本结构（已实测 399 张）：

```
←6 【灵摆】 6→              ← 刻度头行，跳过（刻度从 datas.level 拆）
<P效果正文（可能有①编号）>
【怪兽效果】                 ← 分隔标记（ja: 【モンスター効果】）
<怪兽效果正文>
```

- 以 `【怪兽效果】` / `【モンスター効果】` 为界：**之前 = P 效果段**（`seg_type='pendulum'`，`effect_no=-1`，若 P 效果内有 ① 编号则逐段拆，`effect_no` 用负数 -1/-2…）；**之后 = 怪兽效果**（按 §3.2 拆）
- 刻度头行（`←…【灵摆】…→` / `←…【ペンデュラム】…→`）丢弃

### 3.2 编号效果（含 ①②③ 的卡）

- 正则切分：`re.split(r'(?=[①②③④⑤⑥⑦⑧⑨⑩]：)', desc)`，保留以编号开头的段
- `effect_no` = 编号数字（①→1, ②→2 …）
- **段前的元信息行不是效果**，归入 `seg_type='rule'`，`effect_no=0`：
  - 召唤条件行：`「XXX」降临` / `「XXX」により降臨`
  - 限制行：`这个卡名的①②的效果1回合各能使用1次。` / `このカード名の①②の効果はそれぞれ１ターンに１度しか使用できない。`
  - 这些行信息有价值，可作为后续"1回合1次"维度扩展的素材，但本版本只存文本不打标

### 3.3 无编号效果的怪兽（type & 0x1 且 & 0x20，desc 无 ①）

共 1,624 张（实测）。整段作为一个效果段：`effect_no=1`，`seg_type='monster'`。
多为永续效果或召唤条件，按 §4 正常打标（这类大多 `activation='continuous'` 或 `'none'`）。

### 3.4 魔法 / 陷阱卡

魔法陷阱的主文本**就是"卡的发动"效果本身**，多数无编号（实测魔法 285 + 陷阱 497 无编号）。
整段作为一个效果段：`effect_no=1`，`seg_type='spell_trap'`。

- 若文本内出现 `●` 分点的可选效果（如「从以下选1个发动」），**不拆**，保留整段
- `activation` 默认 `'ignition'`（速攻魔法/反击陷阱/含「双方回合」/「对方回合也能发动」的按 §4.2 改判）

### 3.5 通常怪兽 / 衍生物

- 通常怪兽（type & 0x10，无 & 0x20）：desc 是 flavor 文本，`seg_type='flavor'`，只存文本，所有标签 NULL。**不参与检索**
- 衍生物（type & 0x4000）：同上处理

### 3.6 切分质检

- zh 与 ja 的段数不一致的卡 → 记入异常清单 `split_anomalies`，人工抽查
- 段数分布、各 seg_type 计数必须输出到覆盖率报告（见 §8）

## 4. 五维分类规则

**统一技巧：只在"发动条件子句"里找证据，不要在整段里找。**
发动条件子句 = 段首到「才能发动/発動できる/発動する」之间的部分。取对象、发动位置、时点都写在这个子句里（OCG 立法级模板），效果处理部分出现的同名词是干扰。

对每个效果段，先定位条件子句（ja：`発動できる|発動する|発動できる。` 之前的部分；zh：`才能发动` 之前的部分），再判以下五维。日文判，中文对照。

### 4.1 targets（取对象）

| 判定 | ja 模式 | zh 模式 |
|---|---|---|
| `1` 取对象 | 条件子句含 `を対象と(して｜する)` 或旧模板 `選択して発動` | 条件子句含 `以…为对象` 或旧模板 `选择…发动` |
| `0` 不取对象 | 以上皆无 | 以上皆无 |
| `NULL` 不适用 | `activation` 为 continuous/none 的段 | 同左 |

注意：
- 效果处理部分出现「以…为对象」（如"那之后，可以以…为对象"）**不算**——OCG 要求取对象必须在发动时声明
- 「选…破坏」的「选」**不是**取对象标记（如奈芙提斯之苍凰神）
- 例：装弹枪管暴动龙 ② 条件子句「以自己墓地1只…为对象才能发动」→ targets=1；破灭与终焉之支配者 ③「支付2000基本分才能发动」→ targets=0

### 4.2 activation（发动类型）

| 值 | 含义 | 判定模式（在条件子句/段首） |
|---|---|---|
| `quick` 诱发即时（咒文速度2） | 可在对方回合发动 | 含 `相手ターンでも発動` / `对方回合也能发动`；或段为反击陷阱/速攻魔法主效果 |
| `trigger` 诱发 | 满足事件条件时发动 | 条件子句含 `～場合` / `～時` / `～之际` / `～时` |
| `ignition` 起动（咒文速度1） | 自己主阶段主动发动 | 条件子句含 `自分メインフェイズ` / `自己主要阶段`；或怪兽效果段无条件子句仅有 cost |
| `continuous` 永续 | 无需发动，持续适用 | 段中**不含** `発動/发动`（如「这张卡不会被战斗破坏」） |
| `none` 无需发动（规则类） | 召唤条件/规则文本 | `seg_type='rule'` 的段 |

优先级：`quick > trigger > ignition > continuous`。段含「发动」但无事件、无主阶段字样的怪兽效果，默认 `ignition`。

### 4.3 location（发动位置）

在**条件子句**中找位置词（不是整段——cost 和处理里的位置词是干扰）：

| 值 | ja 模式 | zh 模式 |
|---|---|---|
| `hand` | `手札のこのカード` / `このカードを手札から` / `手札から(捨てて｜見せて)…発動` | `手卡的这张卡` / `从手卡` |
| `grave` | `このカードが墓地に存在する場合` / `墓地のこのカード` | `这张卡在墓地存在` / `墓地的这张卡` |
| `banished` | `このカードが除外された場合` / `除外されているこのカード` | `这张卡被除外的场合` / `除外的这张卡` |
| `deck` | `デッキから…発動`（少见） | `从卡组…发动` |
| `field` | 以上皆无（怪兽的默认值） | 同左 |
| `NULL` | continuous/none 段 | 同左 |

注意：「从手卡丢弃**作为 cost**」（如神光之宣告者「从手卡把1只天使族送去墓地才能发动」）说明这张卡本身在**场上**发动，cost 从手卡出——location 看的是**这张卡在哪**，不是 cost 素材在哪。判定锚点是「这张卡/このカード」的位置表述。神光这类无位置字样的 → field。手坑类（灰流丽「把这张卡从手卡丢弃才能发动」）→ hand。

### 4.4 timing（时点 + 必发/选发）

仅对 `trigger` / `quick` 段判定，其余 NULL：

| 值 | ja 模式 | zh 模式 | 含义 |
|---|---|---|---|
| `when_optional` | `時に発動できる` | `时，才能发动` / `时才能发动` | **会错过时点**（选发+时系） |
| `if_optional` | `場合(に｜、)発動できる` / `場合(に｜、)(選んで)?発動できる` | `场合才能发动` | 不会错过时点（选发） |
| `if_mandatory` | `場合(に｜、)発動する`（无 `できる`） | `场合发动` / `场合，发动`（无「才能」） | 必发 |

**只存原子标签，不存"会不会错过时点"的结论**——查询期由 DSL 组合（时系+选发 → 会错过）。

### 4.5 negate_type（无效类型）

| 值 | ja 模式 | zh 模式 |
|---|---|---|
| `activation` 发动无效 | `の発動を無効` / `発動を無効` / `発動無効` | `发动无效` / `的发动无效` |
| `effect` 效果无效 | `効果を無効` / `効果は無効` / `効果無効`（且无发动字样） | `效果无效` / `的效果无效化`（且无发动字样） |
| `NULL` | 不含无效语义 | 同左 |

注意歧义句：「发动的效果无效」（如技能抽取型）= 效果无效（`effect`），判定时 `発動を無効` 优先于 `効果を無効`。
召唤无效（`特殊召喚を無効`）不算本维度，属于动作类型，由 seg_category 承接。

## 5. seg_category（段级动作类型）

**不自建动作分类，用官方 category 的同一套 32 位。** 赋值规则：

1. **单效果卡**（全卡只有 1 个效果段）：`seg_category = datas.category`（直接继承）
2. **多效果卡**：默认所有段继承卡片 `category`（粗），然后对**能模板判定的段**做精化——例如段内出现「破坏」且非被动句式（见 §5.1）的段才挂破坏位；判不了的保持继承值
3. `seg_type='rule'/'flavor'` 的段：`seg_category = 0`

### 5.1 主动 vs 被动（破坏类的方向判定）

官方 category 的破坏位（0x1/0x2）= **主动破坏**，耐性位（0x1000000/0x2000000）= **抗性**，官方已区分。我们做段级精化时遵循同一语义：

| 句式（在效果**处理**部分判，不在条件子句） | 方向 |
|---|---|
| `不会被…破坏` / `～ない`（`破壊されない`） | 被动/抗性 → 挂耐性位语义，不挂破坏位 |
| `被…破坏的场合` / `破壊された場合` | 被动触发条件 → 不是破坏动作 |
| `作为代替…破坏` / `身代わり` | 代替破坏 → 非主动 |
| 处理句中 `…破坏。` / `…破壊する。` 且主语是效果作用对象 | **主动破坏** → 挂破坏位 |

魔陷破坏（0x1）vs 怪兽破坏（0x2）的区分：看处理句的破坏对象含「魔法·陷阱/魔法・罠」还是「怪兽/モンスター」；全场破坏（「场上的卡全部破坏」）两位都挂。

## 7. 查询使用方式（执行层如何消费）

DSL 示例：「不取对象破坏卡片的仪式怪兽」

```json
{
  "must": [
    {"field": "type", "op": "bit_has", "value": 128},
    {"field": "type", "op": "bit_has", "value": 1},
    {"field": "category", "op": "bit_has_any", "value": [1, 2]},
    {"field": "effects", "op": "exists", "where": {
      "targets": 0,
      "seg_category_any": [1, 2]
    }}
  ]
}
```

编译成 SQL：

```sql
SELECT d.id, t.name FROM datas d JOIN texts t ON d.id = t.id
WHERE (d.type & 128) AND (d.type & 1)
  AND (d.category & 3) != 0
  AND EXISTS (
    SELECT 1 FROM card_effects e
    WHERE e.card_id = d.id
      AND e.targets = 0
      AND (e.seg_category & 3) != 0
  );
```

「会错过时点才能发动的卡」= `timing = 'when_optional'`。
「在手卡发动的诱发效果」= `location='hand' AND activation IN ('trigger','quick')`。
「发动无效（不是效果无效）的康」= `negate_type='activation'`。

**参考实测**：用本规则的手写版跑"不取对象破坏的仪式怪兽"：category 粗筛 160→36，效果段精修→22 张，名单人工抽查全对。

## 8. 验收标准

实现完成后必须产出**覆盖率报告**，包含：

1. **切分统计**：总卡数、各 seg_type 段数、zh/ja 段数不一致的异常清单（目标：异常 < 2%）
2. **五维判定率**：每维"规则可判 / NULL / 判不了（待 LLM）"三档计数。目标：规则可判 ≥ 85%，待 LLM ≤ 15%
3. **与官方 category 的审计对比**：
   - A = category 有破坏位的卡集合，B = 我们的 seg_category 判出破坏位的卡集合
   - A−B（我们漏的）和 B−A（我们多判的）各抽样 20 张人工复核
   - 注意：官方自身也有漏标（实测案例：电子化天使-美朱濡- 的炸场没挂破坏位），审计差异不全是我们错
4. **金标集回归**：至少 30 张人工标注的卡（见 §9 建议清单），每次改规则全量回归，准确率要求 100%（错了就修规则，不许放过）

## 9. 已知边界与不做的事

1. **不做在线推理**：本模块离线跑一次，产出表后查询期零 AI。
2. **LLM 补标是离线一次性**的：规则判不了的段打包送 LLM，`confidence='llm'`，结果落库永久复用。预估占比 ≤ 15%（主要是 2017 年前的老文本）。
3. **中文翻译有损**：任何维度在 zh 上判不出但 ja 能判的，以 ja 为准。zh 的 `text` 字段仅供展示。
4. **官方 category 漏标不补**：电子化天使-美朱濡- 这类官方漏挂位的卡，线上不兜底，记入审计报告即可。
5. **多效果可选分支（● 分点）不拆段**：如崇光之宣告者一段内两个 ● 分支，整段打标（该段 targets=0 即可，分支细化留待后续版本）。
6. **灵摆效果的 location**：P 效果段在灵摆区发动，本版本 location 记为 `field`（P 区属于场上），如需精确可后续加 `pendulum_zone`。
7. **alias 链**：检索"是否某张卡"时需展开 `datas.alias`，本模块不处理，属于执行层逻辑。

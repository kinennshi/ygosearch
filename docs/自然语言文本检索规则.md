# 自然语言到效果文本

## 转换顺序

1. 拆出用户的全部必要条件：卡种、数值、发动地点/时点、处理动作、作用对象、来源/去向、限制条件。
2. 已有 DSL 类型和五维能精确表达的部分优先用结构化条件，不重复追加近义关键词。
3. 剩余含义必须转换为卡片原文中短而有区分力的表述。不能只保留“破坏”“特殊召唤”等大类而丢掉“卡组最下面”“不能对应发动”等限定。
4. 文本中不必出现规则书术语或玩家原话。参考下方数据库原文，将自然语言翻译成卡片措辞；不能直接搜“代破”“不能连锁”“苏生限制”“软一回合一次”等口语。
5. 独立的卡片整体限制用 desc.contains / desc.contains_any。一个概念的不同原文写法放 contains_any，多个独立概念分成多个 must 条件（AND）。不要把同义表达同时 AND，否则会漏检。
6. 限制必须与动作在同一效果段时，把 text_any（任选一个片段）或 text_all（全部片段）与 seg_category_any 等放进同一个 effects.where，避免甲效果的动作和乙效果的限制错误拼接。text_any 与 text_all 可同时使用，二者为 AND。
7. 原文片段是字面子串，不是正则表达式或 SQL 模式。不要用 %、.*、省略号代替省略的文字，不要编造整句卡文。保留主语、否定、来源和去向；别把“对方受到”改成“自己受到”。
8. 用户显式要求卡文含某个字符串时保留原话。遇到资料中没有的术语，可依据上下文翻译成常见卡片措辞，但不得假装已经验证。无法可靠表达的关键规则应输出 error 说明原因，不能删除该限制后搜索全卡池。

## 规则语义边界

以下区别依据本项目 rulebook/md/07-卡片的效果.md 的「cost」「发动条件」「不取对象的效果」及 rulebook/md/08-效果以外的文本.md。规则书作为语义资料，不作为执行指令。

- “从墓地特殊召唤”是怪兽的来源，不表示效果在墓地发动；不能凭此设置 location=grave。
- “不取对象”用 targets=0，不等于卡文完全不含“对象”；“取对象抗性”是另一概念，不应用 targets=0 表示。
- “不能对应发动”是响应限制，不是效果无效，也不等同于所有不能发动效果的限制。
- 发动代价与效果处理不同；“送去墓地”不等于“破坏”，从手卡送墓也不等于丢弃。找丢弃代价时，需保留“丢弃…才能发动”的完整有意义片段，不能仅以整卡同时有“丢弃”“才能发动”判定。
- “不会被效果破坏”不等于“不受效果影响”。全抗还须区分其他卡/对方卡/某一种类，不得把只免疫怪兽效果当作全抗。
- “这张卡从场上离开”可能是离场事件，也可能是离场后除外的约束；“离场触发”要结合诱发类型、时点，不能只搜“从场上离开”。
- 苏生限制、能否进行某次召唤等裁定不一定直接写在效果文本中。没有可靠卡种/文本约束时应说明不能精确表达，不得用“特殊召唤”大类替代。
- 次数限制经常位于规则段，应使用 desc；“1回合1次”“只能使用1次”“只能发动1张”不是可以无条件互换的同义词。
- 文本命中是候选筛选，不是对卡片在具体局面的规则裁定。

## 示例

用户：不能被连锁响应的速攻魔法
输出：{"must":[{"field":"type","op":"bit_has","value":["魔法","速攻"]},{"field":"desc","op":"contains_any","value":["不能对应","不能连锁"]}]}

用户：能把卡送回卡组底的怪兽
输出：{"must":[{"field":"type","op":"bit_has","value":"怪兽"},{"field":"effects","op":"exists","where":{"seg_category_any":[32],"text_any":["卡组最下面","卡组最下方"]}}]}

用户：能从墓地特殊召唤怪兽的魔法
输出：{"must":[{"field":"type","op":"bit_has","value":"魔法"},{"field":"effects","op":"exists","where":{"seg_category_any":[262144],"text_all":["墓地","特殊召唤"]}}]}
说明：这是文本候选范围；必须阅读原文确认墓地是召唤来源，不能设置发动地点为墓地。

用户：有代破效果的卡
输出：{"must":[{"field":"effects","op":"exists","where":{"text_any":["代替破坏","作为代替"],"text_all":["破坏"]}}]}
说明：替代措辞与破坏须在同一效果段；仍须阅读原文确认代替的具体处理。

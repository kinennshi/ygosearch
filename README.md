# YGOSearch

**游戏王卡片自然语义检索器。**

记得一种效果，却想不起卡名？想找符合特定条件的卡，又不想逐张翻卡表？YGOSearch 可以帮你从本地卡库里筛选。

你可以直接勾选条件，也可以用一句话描述需求，例如：

- 「不取对象破坏卡片的仪式怪兽」
- 「不能被连锁响应的速攻魔法」
- 「能把卡送回卡组底的怪兽」
- 「让自己受到的伤害变成 0 的卡」

程序在你的电脑上运行，通过浏览器使用。**手动检索无需 AI，也不需要 API Key。** AI 检索需要配置在线 API 或本地模型服务。

## 能做什么？

| 功能 | 用法 |
|---|---|
| 按卡面信息找卡 | 筛选怪兽／魔法／陷阱、属性、种族、字段、卡池和禁限情况 |
| 按数值找卡 | 设置攻击力、守备力、等级／阶级、灵摆刻度和 LINK 值范围 |
| 按效果找卡 | 筛选破坏、除外、特殊召唤、无效等效果，以及仪式相关、里侧相关、伤害免疫 |
| 缩小效果范围 | 指定是否取对象、发动类型、发动地点、发动时点和无效类型 |
| 用自然语言找卡 | 让 AI 把你的描述整理成筛选条件，再查询本地数据库 |
| 查看与比较 | 查看完整效果、效果段标注，在详情中切换上一张／下一张 |

界面采用游戏王卡面风格，支持横版和竖版布局。结果每页显示 100 张，支持翻页、页码跳转和排序。

## 快速开始

需要 **Python 3.10 或更新版本**。前端不用安装 Node.js，也不用单独编译。

### 1. 下载项目

在 GitHub 上选择 **Code → Download ZIP**，解压后进入项目文件夹；也可以使用 Git：

```bash
git clone https://github.com/kinennshi/ygosearch.git
cd ygosearch
```

下面的命令都在项目根目录运行，也就是能看到 `README.md` 和 `requirements.txt` 的目录。

### 2. 安装依赖

**macOS / Linux：**

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

**Windows PowerShell：**

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 3. 启动并打开网页

**macOS / Linux**（已激活虚拟环境）：

```bash
python -m flask --app core/app.py run --host 127.0.0.1 --port 5055
```

**Windows PowerShell：**

```powershell
.\.venv\Scripts\python.exe -m flask --app core/app.py run --host 127.0.0.1 --port 5055
```

浏览器打开 **[http://127.0.0.1:5055/](http://127.0.0.1:5055/)**。

使用期间保留终端窗口；按 `Ctrl+C` 停止服务。下次使用只需再次启动，无需重复安装。

仓库已包含卡库和效果索引，首次运行通常无需下载或重建数据。请保留项目目录结构。

## 怎样检索？

### 手动检索

1. 打开「手动检索」，选择需要的条件。没有设置的条件不作限制。
2. 「字段」指游戏王中的卡片系列／字段，例如「DDD」，支持输入名称自动补全。
3. 「文本含」适合查找卡文里的具体措辞。例如输入「卡组最下面」，可以进一步缩小范围。
4. 点击「检索」，查看命中数量和卡片。点击条件摘要可查看本次筛选条件。
5. 点击卡片打开详情；长效果文本也可以直接在结果列表里展开。

几个容易混淆的地方：

- **怪兽能力中的「特殊召唤」**指特殊召唤怪兽这一卡种，例如积木龙；**效果类型中的「特殊召唤」**指卡片具有特殊召唤相关效果。
- **发动地点**指效果在哪里发动。「从墓地特殊召唤」说的是怪兽来源，不一定是效果在墓地发动。
- 同时选择多个效果类型时，命中其中任意一种即可；其他条件会继续缩小结果范围。

### AI 语义搜索

先完成下文的 API 配置，再切换到「AI 语义搜索」，输入一句完整需求。

AI 的作用是**理解你要找什么**，结果来自本地数据库。它会结合两类条件：

- **明确的筛选条件**：例如「暗属性」「攻击力 3000 以上」「不取对象」。
- **卡片原文条件**：效果分类没有覆盖的细节，会尽量转换成卡文措辞。例如「不能连锁响应」对应「不能对应」「不能连锁」等表述。

不同写法可以任选一种命中；要求发生在同一效果里的条件，可以限定在同一效果段内匹配，减少把两个不同效果拼在一起的误命中。搜索后会显示解析出的条件和命中数量，不需要你阅读程序内部的查询格式。

支持「凡骨／白板」「康」「代破」等玩家用语，但**描述越具体，结果通常越容易核对**。建议写清卡种、动作、对象、来源和去向。例如「把对方场上的怪兽送回卡组底」，比「解场的卡」更明确。

目前每次 AI 搜索都是独立查询，不会自动继承上一句话的条件。复杂裁定、特定局面下能否发动等问题，也不能仅凭关键词搜索作出判断。

## 配置 AI 服务

打开「AI 语义搜索」下方的「API 配置」。

| 服务 | 需要填写什么 |
|---|---|
| DeepSeek、GLM、Kimi | 选择服务，填写自己的 API Key 并保存；地址和模型使用项目预设 |
| 本地 AI 服务 | 启动兼容 OpenAI 接口的服务，填写地址和模型名称；可点击「扫描模型」读取服务器上的模型列表 |

本地服务默认地址是 `http://127.0.0.1:8000/v1`。没有启用鉴权时，可以不填 API Key。

在线服务的模型名称和可用性可能变化。预设不适用时，可以修改 [`config.presets.json`](config.presets.json)，或者参考 [`config.example.json`](config.example.json) 手工创建 `config.json`，填写服务地址、密钥和模型名称。

配置保存在本机的 `config.json`，已从 Git 提交中排除，网页不会回显已保存的密钥。使用在线 AI 时，查询内容、规则说明和少量卡片文本参考会发送给你配置的服务；手动检索不调用 AI。

## 卡池与数量怎么理解？

这里的卡池表示卡片的地区归属，**不是某种比赛规则下的可用卡清单**。禁限情况需要另外筛选。

| 选项 | 实际含义 |
|---|---|
| OCG | 所有属于 OCG 的卡，也包括同时属于其他地区的卡 |
| TCG | 所有属于 TCG 的卡，也包括同时属于其他地区的卡 |
| OCG/TCG | 同时属于 OCG 和 TCG 的卡，即两者交集 |
| 简中/OCG | 同时属于简中和 OCG 的卡，即两者交集 |
| 全部，或不选卡池 | 查询本地数据库中的全部卡池 |

选择多个卡池选项时，满足其中任意一个选项即可。

结果还会做两项处理：

- **同名异画只显示一张**，优先显示符合条件的原版；如果只有异画版符合条件，则显示其中一张。
- **衍生物和陷阱怪兽不进入检索结果**，但原始数据库记录保留。

因此，首页显示的原始卡库记录数可能比「全部」检索的命中数多。命中数量与分页按去重后的结果计算。「全部」也只代表随项目提供的本地卡库，不代表实时收录所有新卡。

### 三个按文本识别的效果类型

| 分类 | 识别范围 |
|---|---|
| 仪式相关 | 效果段包含「仪式召唤」「仪式魔法」「仪式怪兽」「仪式卡」之一；仅有仪式卡种不会自动命中 |
| 里侧相关 | 效果段包含「里侧表示除外」或「里侧守备表示特殊召唤」 |
| 伤害免疫 | 效果段包含「伤害变成0」，包括战斗伤害、效果伤害或单次伤害归零 |

这些分类按当前识别规则检索，并非对全部可能句式的穷举。效果段和五维信息由程序自动标注，仅供筛选参考，最终请阅读卡片原文。

## 常见问题

**网页打不开、连接被拒绝怎么办？**

确认终端里的服务仍在运行，并访问启动命令使用的端口。本 README 使用 `5055`。如果该端口被占用，把命令中的 `5055` 换成其他端口，同时修改浏览器地址。

**访问 5000 端口出现 403？**

5000 可能被其他程序占用，macOS 上尤其需要留意。使用本文的 `5055` 启动命令，避免打开了其他服务。

**手动能搜，AI 搜不了？**

先检查 API 配置、模型名称、账户权限和服务是否可连接。本地模型还需要先启动模型服务器。「扫描模型」要求服务器提供 `/models` 接口。

**AI 结果太多、太少或没有结果？**

先查看它解析出的条件，确认有没有把你的意思理解错。尝试明确主语和动作，或减少不必要的限定；也可以用手动筛选和卡文中的短语逐步核对。AI 理解和自动效果标注都可能有误。

**卡库会自动更新吗？**

不会。项目使用随仓库提供的数据库快照。更新卡库后，需要重新构建效果索引并重启服务，步骤见下文。

## 给开发者

### 主要文件

```text
core/                       后端、效果识别、检索和 AI 接口
web/index.html              网页界面，无需前端构建
web/assets/                 卡面主题样式、图标及来源说明
cdb/card_effects.db          构建好的效果索引
cdb/zh-CN/                  中文卡库、字段名称和禁限表
cdb/ja-JP/                  重建效果索引时使用的日文卡库
cdb/en-US/                  英文卡库
rulebook/md/                规则书 Markdown 资料
docs/                       效果分类、玩家用语和文本转换规则
tests/                      回归测试
config.presets.json         AI 服务预设
config.example.json         配置示例
```

手动与 AI 模式共用一套查询格式（DSL）。模型输出先经过校验，再由程序转换为参数化 SQL 查询数据库；AI 不直接生成或执行 SQL。

### 更新效果索引

通常不需要执行。更换卡库后，先停止服务并备份 `cdb/card_effects.db`，确保中文、日文数据配套，再在项目根目录运行：

```bash
python core/build_effects_db.py
```

该命令会重建 `cdb/card_effects.db`，并生成 `cdb/coverage_report.md`。完成后重新启动服务。Windows 可将 `python` 换成 `.\.venv\Scripts\python.exe`。

### 运行测试

在已安装依赖的环境中，从项目根目录分别运行：

```bash
python tests/test_golden.py
python tests/test_app_p0.py
python tests/test_search_updates.py
python tests/test_nl_text_search.py
```

测试包括效果识别、卡池归属、同名卡去重、分页、文本条件和 AI 接口流程。AI 接口测试使用模拟回复，不需要密钥，也不会调用在线服务；它们不代表已验证所有模型的真实理解效果。
